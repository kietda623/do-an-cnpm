# T137 Buyer Commerce Mobile Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` or `superpowers:subagent-driven-development` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Implement Buyer Mobile flows B07–B10 for cart, quote/checkout, order history, and order detail actions using existing API/auth/query infrastructure.

**Architecture:** Use the existing Expo Router `(buyer)` group, `SessionProvider`, `mobileQueryClient`, `ApiPath`, and generated OpenAPI schemas. Put commerce query/action logic and a RAM-only write-intent registry in `features/commerce`; keep route entries thin and each screen focused. On app restart, refetch authoritative cart/order/payment data and reconcile before presenting actions; never persist cache or blindly replay an old write.

**Tech Stack:** Expo SDK 57, React Native 0.86.3, Expo Router 57, React Query 5.104.5, Jest/Jest Expo, Testing Library React Native, generated OpenAPI types.

**Spec:** `docs/superpowers/specs/2026-11-01-mobile-t137-design.md`; authority: `specs/001-marketplace-mvp/tasks.md` T137, `specs/001-marketplace-mvp/spec.md` FR-21–36 / BR-04–08, `specs/001-marketplace-mvp/contracts/api.md`, `docs/design/screen-flows.md` B07–B10.

## Global Constraints

- Preserve Expo 57.0.30 and React Native 0.86.3 pins; add no dependency or state library.
- Never persist React Query cache, write intents, access tokens, or refresh tokens in this task; existing SecureStore auth behavior remains untouched.
- Use generated `components["schemas"]` response/request models and `ApiPath`; do not define handwritten DTO copies.
- All money and final totals come from server responses; checkout is all-or-none and uses only selected cart item IDs, address ID, method, and quote ID.
- Same request scope/body reuses one in-memory UUID `Idempotency-Key`; a retry after process restart starts with fresh server reads and reconciliation.
- Queries consume AbortSignals and include the current `user.id` in private query keys; use the existing query retry policy, and keep mutations `retry: false` with explicit UI retries.
- Keep T134 open until Android resume device evidence exists. T137 remains unchecked because it depends on T134. Do not run device/emulator verification; do not work on iOS or Desktop.
- `PRICE_CHANGED` returns only 409 in the current service/test; require an explicit new quote action and do not expect replacement quote data in the error.
- Buyer can display COD payment state but cannot call Seller/Admin COD collection. Only expose cancel/receive/mock actions allowed by current server order state and versions.

## Review Focus

- Invalid or expired quote, changed price, and stale cart: no checkout side effect; the buyer must review a new server quote. Covered by Task 3 quote/409 tests.
- Network timeout after a write: same intent key/body is reused while process lives; after cold start, server state is fetched before actions. Covered by Tasks 1, 3, and 5 retry/reconciliation tests.
- Partial or blocked cancellation: use parent Order.version for whole-order cancel, SellerOrder.version for one-part cancel, and show blocking part names from 409 details. Covered by Task 5.
- Payment and receive actions: use Order.version for mock-result and SellerOrder.version for receive; do not collect COD from Buyer UI or show receive before delivery/payment. Covered by Task 5.
- Account switch or stale query: previous Buyer cart/orders must not appear under a new user, and aborted queries must not restore stale data. Covered by Tasks 2, 4, and 5.

- Create: `apps/mobile/src/features/commerce/write-intents.ts`

**Interfaces:**
- Produces `WriteIntent = { idempotencyKey: string; eventId: string }`.
- Produces `WriteIntentRegistry.getOrCreate(scope: string, body: unknown): WriteIntent` and `complete(scope: string, body: unknown): void`.
- The production instance is module-scoped RAM only. `scope` includes `user.id`, method, canonical route, and logical action. Canonical body fingerprint ignores object key order.
